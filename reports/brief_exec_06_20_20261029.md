## 1. What the runner does now

```
python tools/tys_kernel_bench.py --all [--ids p06,p07] [--jsonl path] [--restart-every N]
```

Per brief: seed the deterministic workspace → submit a work order whose single
coding step carries `params.acceptance = {required_files, commands}` → execute
through `run_kernel(coding_agent=True)` → validate the artifact semantically →
run the check commands → append one JSONL record.

Each JSONL row carries everything the order asked for:

| field | content |
|---|---|
| `kernel_status`, `kernel_reason` | the kernel's verdict and why it stopped |
| `validator` | kind, detail and the full check tree, including the semantic block |
| `commands` | each command, its exit code and its stdout/stderr tail |
| `provenance` | sha256 + byte size of the artifact, sha256 of every file in the tree |
| `semantics` | the domain spec that was applied to this brief |
| `lane` | `coding` (model) or `tool` (deterministic producer) |
| `seconds`, `task_id` | timing and the Ty work-order id |

**Three briefs are not model work and are labelled so.** `p11` (label.png) is
composited by `pouch_label`, `p13` (canvases.json) by `tools/social_canvases.mjs`,
`p14` (ad.mp4) by the FFmpeg probe. They still run through the kernel with a
deterministic executor and are recorded as `lane: "tool"`.

## 2. Semantic validation (Task 3)

`agent_kernel/content.py` gained a semantic layer that runs alongside the
keyword/type checks. A pass now means the artifact is the *kind of document it
claims to be*.

| check | what it proves | measured effect |
|---|---|---|
| **patch arithmetic** | every `@@ -a,b +c,d @@` header matches its body: `b` = context+removed, `d` = context+added | rejected the local 27B's diff that declared 7 lines and carried 8 |
| **required JSON keys** | the brief's keys are present and not empty | p08 needed `run_id`, `status`, `checkpoint` |
| **placeholder markers** | no line-leading `TODO`/`TBD`/`FIXME`/`XXX`, no `TODO:` | p18 was passing on keywords with a TODO still in the handoff |
| **sentence floor** | the document says something, per-brief | p10 digest, p03 refactor plan |
| **required headings** | named sections exist | p07 `Host`/`Grant`, p16 `Gate`/`Lane`, p18 `Evidence`/`Next step` |
| **unchanged-from-seed** | the artifact is not a byte-identical copy of the stub it started from | p07/p16/p18 hand you a stub to finish |

The per-brief specs live in one table in the runner, not in
`eval/projects/ns_proj_20.json`: the benchmark definition was not edited, so no
scoring bar was tuned to a result.

**The bar is inside acceptance, not applied afterwards.** `tools/diff_check.py`
is invoked by the work order itself, so a malformed hunk comes back to the model
as an observation it can repair — the same lesson as the original p01 defect:
*a loop that cannot see the failure cannot fix it.*

## 3. Defects found while doing this

1. **p01 at the kernel level (real, fixed).** `agent_kernel/tys_adapter.py` turned
   a step that declared `params.acceptance` into a single
   `Acceptance(..., "executor_ok")` — the lane grading itself. Every such node
   could only pass if the loop said it had passed, so a node with the files
   written and the tests green was still blocked. `_derive_acceptance()` now
   builds `artifact_exists` + `command` assertions from the step spec, and the
   kernel verifies the workspace independently.
2. **Single-slot context pollution (real, fixed in the harness).** llama.cpp
   serves one slot with LCP reuse. After a long brief (`p01`, 53 s, many turns)
   the next brief degraded and wrote nothing: the same brief passed alone and
   failed immediately after p01. The harness now restarts the worker per brief
   (`--restart-every 1`, measured before/after).
3. **Command normalisation (my bug, fixed).** `_default_command` returned a flat
   list where the caller expected a list of lists, so every command was executed
   character by character. The first sweep reported 0/20 with `WinError 2`
   because of it.
4. **Tool executor factory (my bug, fixed).** the kernel calls
   `coding_factory(node)(node, plan)`; the factory returned the *result* instead
   of an executor, so p11/p13/p14 could never run.

## 4. Results

Three full sweeps with per-brief isolation:

| sweep | passed | failed | failed briefs |
|---|---|---|---|
| `184244Z` | **18/20** | p01, p19 | patch written, not applied / not applied |
| `185528Z` | **19/20** | p01 | hunk header 7 vs body 8 |
| `190955Z` | **18/20** | p01, p07 | hunk header 7 vs body 8 / the word `expiry` absent |

Earlier sweeps (`182639Z` 9/20, `183218Z` 12/20) ran before defect 1 and 3 were
fixed and are kept only as history.

Typical times: 3–10 s per model brief, 1.4 s / 0.1 s / 0.0 s for the three tool
briefs, ~11 minutes for the full isolated sweep.

### The two failures, precisely

* **p01** — the fix is correct (`3 passed`, `pytest` exit 0) but the 27B counts
  the hunk body wrong: `@@ -1,7 +1,7 @@` over an 8-line body. It repaired for 55 s
  and did not converge. When the header counts are right (two runs), it passes in
  ~10 s.
* **p07** — a structurally complete runbook (Host and Grant present, no TODOs, 6
  sentences) that never uses the literal word `expiry`; the brief's `terms` list
  requires it. Keyword-level, and the objective names the word; the model still
  paraphrases it.

Both are model-capability limits at this size, measured — not validator bugs. The
honest options are a larger worker, a deterministic post-pass that recomputes hunk
headers, or the AST/symbolic edit lane the original architecture document argued
for. None of those is in this change.
