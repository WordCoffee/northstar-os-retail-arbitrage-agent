# Ty's eyes — vision supervision for Tys Assistant (2026-11-05)

**Owner brief:** "It needs to be able to see if Tys Assistant is staying on track with
the goal and help give Tys Assistant help. I should be able to enable Tys Assistant, and
then Tys Assistant's Vision, and have them work together… they should work together as
Tys Assistant's eyes, helping him navigate and improve/build."

Built and verified. Two dependent switches, one vision checkpoint per visible step, the
verdict fed back as guidance, a cobalt ring while the eyes are armed, and the assistant
describing the eyes as its own in the operator panel.

## 1. What exists now

| Piece | Path | Behaviour |
|---|---|---|
| The eye | `Northstar_backend/agent_kernel/eye.py` | `TyEye.look(goal, image, constraint)` → `on_track` / `off_track` / `unverified` / `disabled`, plus `guidance`. Append-only JSONL journal. Never raises. |
| Vision as acceptance | `agent_kernel/verify.py` (`vision` verifier) | A node can require the eye's agreement: `pass` / `fail` / **`unknown`**. `unknown` is never upgraded to pass. |
| Wiring | `tys_assistant._look_at_step` | After a step that produced an image, the eye looks; the verdict and guidance are attached to the step evidence and written as an `eyes_look` event. |
| Enforcement (opt-in) | `step.params.eyes_enforce` | Off by default (advisory). When set, an `off_track` look fails the step as retriable so the assistant repairs it. |
| Switches | `tys_assistant.set_switches` | `assistant.enabled` (default **on**), `vision.enabled` (default **off**). Vision cannot be armed while the assistant is off; switching the assistant off disarms vision. |
| API | `GET/POST /api/admin/tys/switches`, `GET /api/admin/tys/voice` | Admin-only. Unknown switch names are refused. |
| Ring | `northstar-os-ui/src/components/VisionRing.jsx` + `app.css` | Cobalt ring around the viewport while `vision: true`. |
| Voice | `PERSONA_TEXT`, `LEARNING_LANES`, `voice()` | The assistant's own words about its eyes and its REA learning lanes. |

## 2. The contract that makes it trustworthy

The single most important line in this build:

> `unverified` is never upgraded to `on_track`.

A supervisor that reports success when it could not see launders an absence of evidence
into evidence of correctness. So the eye has four outcomes and the fourth (`disabled`) is
silent:

| status | when | effect |
|---|---|---|
| `on_track` | image read, verdict parsed as pass | no guidance |
| `off_track` | image read, verdict parsed as fail | `guidance` = the model's own reasons |
| `unverified` | no image / no constraint / model down / unparseable answer | recorded, never a pass |
| `disabled` | operator switch off | no model call at all |

Steps that produce no image get **no look**. The eye judges appearance; a coding step is
judged by its acceptance command, and inventing a verdict about text it has not seen is
exactly the failure measured on 2026-11-05 (0.652 character similarity, confidently
invented lines). `test_no_image_means_no_look_and_no_invented_verdict` pins that.

**With `eyes_enforce: true`**: `ok=False, retriable=True`, and the detail carries the
guidance — the eye is allowed to stop the step, and only when the work order says so.

## 4. The ring

`VisionRing` mounts once in the app shell. Cobalt (`--spark #2f6fed`, the system's one
AI-state accent), fixed full-viewport overlay, `pointer-events: none`.

Resource cost, deliberately: one div, two static `box-shadow` layers, **one CSS opacity
animation** (compositor-only, no layout or paint), `will-change: opacity`. No canvas, no
`requestAnimationFrame`, no per-frame JS. Polling is one request every 15 s, paused while
the tab is hidden, and it stops for good on 401/403/404 — a customer surface has no admin
API and must not poll forever. `prefers-reduced-motion: reduce` freezes the ring at a
steady 0.55 opacity.

The ring is driven by the server, not by local state: a ring on screen means the eyes are
really armed.

## 5. The voice

`PERSONA_TEXT` (served in `/state` → `identity.persona`, and in `GET /voice`) reads, in
part:

> My eyes are Ty's Vision: after I build something visible I look at it and judge whether
> it matches the goal. The eyes judge appearance — a label, a layout, a missing subject.
> They do not read code and they do not guess… When a look cannot happen I call it
> unverified, never on track. When my eyes are armed, a cobalt ring sits around the screen;
> no ring means I am not looking. I learn by REA… only through sanctioned paths: the corpus
> learner for public signed-out breadth, Chrome Connect for read-only live capture, and the
> Tool Execution Gateway for audited tool calls.

`LEARNING_LANES` names the four sanctioned paths with their tool, use and hard "never", so
the assistant recommends the right one instead of inventing a fifth:

* `rea_breadth` — `corpus_learner.py`; public signed-out pages, robots honoured.
* `rea_live` — Chrome Connect, read-only; never raw Playwright, never a credential.
* `rea_tools` — `tool_gateway.py`; every attempt audited.
* `rea_gate` — `tools/verify-rea.ps1`; no adoption claim without the gate result.

`eyes_sentence()` turns a real journal record into one line. No record, no line — the
assistant never says it saw something it did not.

## 7. Gates and reconciliation

Local lane only, no Amazon, no spend, no cloud inference, no credential read, no policy or
allowlist change. GPU returned to idle after the live looks.

**V3 hard freeze (rule 1) reconciliation:** this is an owner-requested capability, not an
unrequested new lane, and it adds no customer-facing surface — it is admin/operator only.
Stage 1 status for the touched modules is green (tests above). Recorded explicitly so the
freeze is not quietly reinterpreted.

## 8. How to use it

1. Improvement room → **Tys Assistant & its eyes** card.
2. Turn **Tys Assistant** on (default on), then **Ty's Vision** on. A cobalt ring appears.
3. Any step that produces a render or screenshot is looked at automatically, and the
   verdict lands in the task evidence and the card's "My eyes, last look" line.
4. To make the eye able to *stop* a step, set `params.eyes_enforce: true` on that step in
   the work order, and `params.eyes.constraint` to the exact thing that must be visible.

API equivalent:

```
POST /api/admin/tys/switches   {"assistant": true, "vision": true}
GET  /api/admin/tys/switches
GET  /api/admin/tys/voice?limit=6
```
