## UNIT BREAKDOWN

**Purpose.** Four working capabilities existed only as endpoints. The gap between "it works" and
"it ships" is exactly this unit.

**Steps (5).**
1. `studio_dashboard.py` — one read-mostly router: packages, manifest, file serving, proposals,
   decisions. Mounted next to the other design-studio extensions behind the same guarded import.
2. Safe file serving: a strict name pattern plus a containment check, so a package file can only
   be read from inside its own folder.
3. Proposal decisions: write `decision`, `decided_at`, `status` into the JSON, then move it to
   `approved/` or `rejected/`. A second decision is a `409`, not an overwrite.
4. `Deliverables.jsx` → an Asset Dashboard: preview grid, manifest panel, four lane triggers with
   an asset picker, and approve/reject per proposal.
5. Live verification over HTTP, plus one real trigger from the same endpoint the page calls.

**Self-review catches (4).**
- **A misleading check.** Inspecting `app.routes` showed no design-studio routes at all, which made
  the mount look broken. `TestClient` answered `200` on the same paths — the object graph was
  misleading, the app was fine. Verified through the interface after that.
- **A 500 hidden in a happy path.** `decide_proposal` returned `target.relative_to(ROOT)`, which
  raises whenever the queue points outside the repo (every test, and any operator override). It
  now degrades to an absolute path.
- **A guard that let dotfiles through.** `_safe_name` accepted `.hidden`; the pattern now requires
  an alphanumeric first character, so `.` and `..` can never resolve.
- **The invalid package.** A folder without a manifest is listed and flagged, and its detail
  endpoint returns `422` with the reason. Hiding it would have made the dashboard lie by omission.

**Commit.** `38ec58e8` (router, tests, page, section label).

## DECISIONS

1. **The dashboard reads the disk, not a database mirror.** A cached index would drift from the
   folders the lanes actually wrote; the filesystem is the source of truth and the page renders it.
2. **A package without a manifest is shown and flagged.** The dashboard's job is to tell the truth
   about what is on disk, not to present a tidy subset.
3. **Decisions move files; they never install.** The queue records intent, and the API response
   says "installing remains a separate approved step" — the UI cannot become an installer by
   accident.
4. **Verify through the interface, not the object graph.** `app.routes` said "not mounted";
   `TestClient` said `200`. The interface was right.
