## 3. Migration map — implementing the Master Blueprint without breaking existing function

Blueprint sources: `master-brain/northstar-os-master-plan.md`, `docs/PRODUCTION_BLUEPRINT.md` (§2 data layer, §8.1 auth/tenancy, §8.2 Stripe plans), `Northstar_UI_Design_Guide.md` set, `FIXES_50.md` backlog.

### 3.1 Non-negotiable non-breaking rules (all migrations)
1. **Element IDs / data attributes stay frozen.** `test_ui_display.cjs` (986 asserts) + `test_shell.cjs` (71 asserts) lock the DOM contract (ids, `data-view`, `data-col`, `data-qf-*`, aria states). Any migration must be additive.
2. **`/api/kirkland/scanner` response shape is frozen** (allowlisted fields, `_clean_scanner_product`). New fields only via additive keys; UI is a pure renderer of the contract.
3. **Live-gate semantics never weaken**: every live/paid path keeps a named env gate + §3 envelope. Migration ships with gates off (demo mode, zero network) exactly as today.
4. **Serve-side additive routes only** during a migration window; remove/rename endpoints in a later explicit phase with a new API version prefix if needed.
5. Golden Goose 363-test + full 1556-test baseline must stay green; UI 986/0 and shell 71/0 must stay green.

### 3.2 Design tokens
**Today:** tokens are ad hoc and duplicated — `:root` CSS vars in `static/index.html` (SPA), hub per-service `--sig-accent` theming in `static/northstar-os/index.html`, Golden Goose hex palette in `golden-goose-panel.html`, landing/auth pages each with their own palette. No canonical token file exists.

**Migration:**
1. Author `shared/design-tokens.json` (+ `:root`/light+dark CSS `design-tokens.css`) as the single source (color, type scale, spacing rhythm, radius, elevation, motion).
2. Roll SPA onto tokens **additively**: keep existing var names as aliases (`--text-strong` etc. resolve to tokens), introduce new names alongside — never rename in place.
3. Wrap token adoption behind a theming attr (e.g. `html[data-theme-v2]`) so the old theme is the failover default until the suite passes on v2.
4. Apply same tokens to hub, Golden Goose panel, landing, auth — each as an additive `<link>`/import, with a per-surface visual-diff pass driven by `test_ui_display.cjs` / `test_shell.cjs`.

### 3.3 Subscription catalog migration
**Today:** plan catalog is hard-coded in `Northstar_backend/auth.py::PLAN_ENTITLEMENTS` (foundation $0 / scout $29 / mover $79 / autothink $149 + gate arrays) — matching blueprint §8.2 exactly. Second parallel index: `master_brain_subscribers.py` reads a plans catalog + `master-brain/profiles/manifest.json` (profile → plan, currently T2 master seed = `autothink`). `/api/v1/plans` returns the hard-coded dict. Stripe/billing = **not implemented** (blueprint §8.2 is the target).

**Migration:**
1. Materialize catalog as `shared/subscription-plans.json` (or `config/plans.json`) with `catalog_version`, plans, price_cents, gate arrays; keep `auth.PLAN_ENTITLEMENTS` as a thin compatibility shim that loads the JSON (single source).
2. `master_brain_subscribers.load_plans()` points at the same catalog; add a catalog-vs-code smoke test so the two can never drift again.
3. `/api/v1/plans` reads catalog; add `GET /api/v1/plans/{id}`.
4. Add Stripe-migration types (plan_id, tenant_id, status, period) to `ops/schema.sql` users table + a `plan_migrations` log table — forward-compatible with Oracle PG plan.
5. Legal-order guard: catalog changes must never grant a gate the operator hasn't explicitly approved; entitlements are read-time checks only.

### 3.4 Golden Goose workspace
**Today:** standalone panel (`/golden-goose/` → `agents/golden_goose_finder/static/golden-goose-panel.html`) + router `/api/golden-goose/*` (`scan-mock`, `scan`, `opportunities`, `categories`, `health`). Hub lists "Golden Goose" as a sourcing sub-view but the hub is zero-network by design.

**Migration:**
1. Embed the panel as a real sub-view in `static/northstar-os/index.html` behind the existing sourcing tab strip; wire only when `NS.gates` for golden-goose is on (hub stays demo until then).
2. Factor panel JS from inline `<script>` into a module (`ggWorkspace.js`) exported like the hub's `NS.hub` module so the shell harness can contract-lock it.
3. Add workspace-scoped filters/persistence (category/store/roi/monthly-sales) to localStorage with the same `schema_version` pattern as the scout filters.
4. Keep `/api/golden-goose/*` stable; add `GET /api/golden-goose/reports` (history/replay — FIXES_50 #42/#61) additively.

### 3.5 Credit ledger
**Today:** three disjoint accounting surfaces — `quota_tracker.py` (JSON quota state), `agents/.../free_tier_registry.py::FreeTierLedger` (per-provider attempt ledger with refunds), `enrich_manifest_run.py` worst-case pre-request reservation. Plus `add_idempotency.py` existing.

**Migration:**
1. Single ledger table in `ops/schema.sql`: `credit_ledger(id, scan_id, provider_id, task_type, asin, delta_credits, cost_usd_cents, idempotency_key UNIQUE, ts, error_code)` + `idempotency_key = sha256(provider:task:asin:fingerprint)`.
2. `FreeTierLedger`/`quota_tracker` become readers/writers against it during the migration window (dual-write then flip), so live behavior and tests don't break.
3. Read-only endpoints: `GET /api/golden-goose/credits` (balanance per provider, 20%-remaining warn config — blueprint §8.4 "credit tracking"). Never a debit/approval endpoint in the UI.
4. Budget guardrails (envelope semantics: named approval → credit estimate → execution → stop-on-exhaustion; circuit-breaker from `costco_live_runner`) stay enforced at the ledger boundary.

### 3.6 Tenant isolation
**Today:** single `users` table + JWT `plan` claim; `auth_deps.get_current_user` falls back to an anonymous `foundation` demo user when no token (ensures UI works pre-auth); per-profile isolation exists only as `master-brain/profiles/*.md` with `manifest.json` + `master_brain_profiles.py` fail-closed resolver (local_default active; login_session/ip_address/two_step_auth are registered-but-future).

**Migration:**
1. Add `tenant_id` to users + data tables (`ops/schema.sql`); scope every `data_layer` query by tenant with an optional `tenant_id` filter param defaulted to the anonymous tenant so demo mode is preserved.
2. JWT gains `tenant_id` claim; `auth_deps` resolves tenant from token, continues to return the demo payload when absent.
3. Plan gating becomes per-tenant (`user_has_entitlement(tenant_id, gate)`), with the subscriber manifest kept as the authoritative profile↔tenant mapping.
4. Gateway/audit entries gain `tenant_id` for isolation (append-only `audit.log.jsonl` gains the field; old entries stay valid).
5. Storage for scan/cache profiles: namespace cache keys (`t2.kirklandScout.*` → `t2.<tenant>.kirklandScout.*`) with a read-fallback to the legacy key so existing local data is not lost.
6. Golden Goose reports dir: `data/golden-goose-reports/` → per-tenant subdirs behind the existing report loader (mtime/live-preference logic preserved).
