# M0.5-spike — can the coding lane write acceptable fixes?

**Purpose.** Decide the author/evaluator design before building it. If the local lane cannot
produce patches that pass their own acceptance checks, a "best-of-N auto-repair" would be a
pretend evaluator, which is worse than no loop.

**Method (fixed, not tuned after seeing results).** Five real problems. Three candidates each
via the coding lane (`run_kernel(coding_agent=True)`, local model). A candidate counts as
solved only if **all three** hold:

1. the target check passes (named below);
2. the full backend suite is green **by test name** (`tools/check_regression.py`);
3. the semantic validators accept the diff (`agent_kernel/content.py` + guardrail fingerprint).

## The five (chosen for diversity, not for ease)

| # | Problem | Target check | Why it is a fair test |
|---|---|---|---|
| S1 | `test_cancel_leased_job_cooperative` races: the worker can reach `SUCCEEDED` after a cancel request (`illegal transition cancel_requested -> succeeded`) | That test, 20 consecutive runs under load | A real concurrency bug in product code; needs judgement, not a one-line patch |
| S2 | `picture_scorecard.product_fidelity` cannot score a composite whose subject detector picks the background | New test: fidelity accepts an explicit `product_box` and scores ≥85 on `lifestyle_linen_composite.png` | Requires reading two modules and extending an API without breaking callers |
| S3 | Documents page fails AA contrast (heading + subtitle) | `ux_scorecard` readability gate on `/ui/documents` | CSS/design-system change with a measurable gate |
| S4 | A+ page renders Shiitake art under a Lion's Mane headline | New test: a page whose plate OCR contradicts the copy is refused | New guard + OCR integration |
| S5 | `render_text_guard` cleans but leaves faint smudges; no plate-cleanliness score | New test: a plate with residual marks below a threshold is reported, not silently passed | Small, self-contained, needs a measurement idea |

## Scoring

| Outcome | Interpretation |
|---|---|
| ≥ 3/5 solved | Build **local best-of-N** (offline, free) |
| 1–2/5 | **Hybrid**: local proposes, the already-paid DeepSeek lane authors, local verifies |
| 0/5 | **Stop and report.** The loop becomes detect-and-prepare; no pretend evaluator |

Every attempt is recorded (candidate diff, check result, reviewer verdict) in
`state/evidence/spike/<slug>/` so the decision is reproducible.

## Why these five and not the queue's top items

The queue's top items are product work. The spike measures *repair capability*, so it needs
problems with unambiguous pass/fail and a spread of difficulty: one concurrency bug, one API
extension, one design-system change, one new guard, one measurement idea. If the lane can do
S1 and S2, it can do most of the queue.
