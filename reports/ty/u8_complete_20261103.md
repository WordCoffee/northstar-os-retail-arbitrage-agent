# U8 final — package front/rear mode and the dieline overlay

**VERDICT: PASS.** U8 is complete and tagged `ns-ux-U8-complete` (`dacf9a32`). Package panels keep
independent layer trees, the dieline overlay draws the print lane's own guide geometry, and the
overlay provably cannot reach an export.

## Unit breakdown

**Purpose.** Close U8: dual-panel package mode with a live dieline overlay on the studio canvas,
without weakening anything that already shipped.

**Steps taken**

1. `lib/studioCanvas.js` — `switchPanel(doc, panelId)` moves the active layer list into
   `doc.panelLayers[old]` and loads the target panel (a fresh background when it has none).
   `panelCounts(doc)` feeds the switcher labels. Switching is an ordinary document change: undoable,
   autosaved, and it never clears the history stack.
2. `lib/dielineOverlay.js` — `PANELS`, `GUIDE_KINDS`, `panelRect`, `panelSize` (4 px/mm),
   `guidesForPanel` (normalises bleed/trim/fold/safe to the ACTIVE panel, clips to it, filters by
   kind), `describeOverlay`.
3. `Northstar_backend/design_studio_print.py` — `POST /api/design-studio/print/dielines/geometry`
   returns the guide layers of the SAME `build_from_template` the print lane renders, plus the panel
   boxes and the print lane's own caveat.
4. `CanvasWorkspace` — panel tabs (Front / Rear / Side-gusset) for the `package` content type, an
   attach/reload-dieline action, per-kind guide chips, and an SVG overlay passed to `Stage`.
5. `Stage` — additive `overlay` prop rendered inside the artboard; `pointer-events:none`.

**Self-review (5 failure modes, each tested)**

| Risk | Result |
|---|---|
| Switching panels loses the other panel's layers | round-trip test: front 2 layers → rear 1 → add → front still 2 with the headline → rear still 2 |
| Switching clears undo/redo | it is a pushed document change; the stack is untouched (unit + e2e) |
| Overlay drawn for the wrong panel | `guidesForPanel` clips to the panel box; a guide outside it is dropped, not moved |
| Overlay leaks into the PNG/PDF | the overlay is DOM-only; exporting with it on and off yields **identical byte counts** (e2e assertion) |
| Overlay geometry drifts from the dieline | the endpoint uses the print lane's own builder; a test asserts width/height/trim counts match `build_from_template` |

## DECISIONS

- Panels live in the document (`panelLayers`) and switching is recorded — a half-finished rear panel
  must survive a reload, and the requirement was "do not clear" history, not "do not record".
- The overlay is an SVG in the DOM rather than a canvas draw, so export exclusion is structural, not
  a flag someone can forget.
- Guide geometry comes from the print lane's builder; a second geometry source would be able to
  disagree with the dieline it is drawn over.
- The artboard takes the panel's true size at 4 px/mm once a dieline is attached; a normalised
  overlay on an unrelated aspect ratio would distort the trim.
- The geometry fetch retries once behind `Retry-After` (the 30/min anonymous bucket), same as the
  PPC lane.
