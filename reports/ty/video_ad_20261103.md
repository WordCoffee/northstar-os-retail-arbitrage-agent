# A real vertical video, end to end, with every stage checked

**Date:** 2026-11-03 · **Commits:** `8d4dd259` (capstone), `a637cd2f` (length + plate fixes) · **Tag:** `ns-video-ad-20261103` · **Probes:** t18 PASS, t14/t15 PASS · **Tests:** 35 passed across the seven video files.

The creative scan's last dependency chain is now one command:

```
script -> scenes -> per-scene Wan clips -> stitch -> captions -> audio -> checks
```

`Northstar_backend/video_ad.py` runs it. The scene renderer is injectable for tests; the default uses
the local Wan lane from a supplied product picture. A file is returned only when every stage's own
contract passes; otherwise the final is deleted and the failing stage is named.

Frames inspected at 1.0 / 4.5 / 8.0 / 11.5 / 14.0 s: the pouch picture is full-height, the caption

The first 3 s attempt produced **2.844 s / 84 frames**: the ducked bed ended with the voice, the mix
followed it, and `-shortest` dropped six frames. `video_audio` now pads the voice to the picture's
duration before the sidechain, trims the mix to it, and applies one bounded linear gain correction
after loudnorm. The 15 s master is the result of that fix.

## API (plan first, render on confirmation)

`POST /api/design-studio/video-ad/plan` returns the scene plan and the sampler clip count **without
touching the GPU**; `POST /render` requires `confirm: true`, checks the plate and the armed lane, and
starts a background job; `GET /jobs/{id}` exposes status, stage, reason and the manifest.

Live plan (TikTok, 15 s):

```
dry_run True clips 8 scenes 5 sum 15.0
0 hook    [73]
1 benefit [57, 57]
2 proof   [53, 49]
3 product [53, 49]
4 cta     [73]
compliance True
```

A failed stage leaves the job `failed` with the reason; a done job carries its manifest. The plan
route exists so a 15 s request (8 sampler clips) cannot be started by a typo.

## Honest gaps

- **The 15 s master is rendered and checked, but its scenes are still single-take.** Five scenes, eight
  sampler clips, one source picture; distinct scene shots would need distinct plates.
- **Short windows compress beats.** At 3 s the five scenes are 0.57 s each; the planner scales to fit
  rather than dropping beats. A 3 s ad would be better with three scenes; that is a planner rule to
  add, not a claim.
- **The voiceover is a continuous track**, not aligned to scene cuts. `voice_fits_scene` flags
  overruns; nothing time-stretches.
- **Captions cover the label's net weight.** The plate is opaque and readable, but a top-third
  placement would preserve the product copy. Operator choice.
- **The Wan render is 480×832 upscaled to 1080×1920.** Soft by construction on this box.
- **No HTTP endpoint yet.** The service can do it through `video_ad.produce`; exposing it as a route
  (with a job and a progress channel) is the next integration unit.
- **Amazon ad presets remain `verified: false`.** They render and check against the working
  assumption, and the manifest says so.
