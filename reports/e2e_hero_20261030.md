## 4. What the run exposed — two defects, both fixed, one still open

**4.1 FLUX 3 ignores "no text".** The prompt said *"no text, no lettering, no logo, no watermark"*.
The render came back with **8 OCR boxes**: `9RGIA1NIIC`, `Musriroom`, `Mutlnofliar`, `Povder`.
This is not a prompt-wording problem, it is the model's behaviour — which is exactly why the repo
has a text gate. The pipeline now runs `check_text_in_image` → `clean_text_regions` → re-check, and
**refuses to ship** if lettering survives. This run: 8 boxes → 8 cleared → **0 boxes**.

**4.2 The contact shadow was a sticker.** First implementation drew an opaque grey ellipse. It read
as a grey blob under the pouch, because the subject was centred with no room beneath it. Now the
shadow is a heavily blurred **black alpha layer composited onto white**, and the subject is lifted
3% so the shadow falls *below* it. A regression test asserts the shadow is a soft ramp (≥4 tones,
darkest between 190–245) rather than two flat tones.

**4.3 STILL OPEN — the artefact is not shippable.** `clean_text_regions` reconstructs each glyph zone
from its surroundings, which on textured kraft leaves **visible soft smudge patches**, and one small
low-contrast string (`ß5sr10mm0`) is still legible in the image even though the OCR gate reports 0
boxes at its 0.35 confidence floor. So the gate passed and the human eye does not.

That is a real limit of "render a blank pouch, then erase the lettering". The correct fix is the
path the repo already has: **never ask the image model to produce a label at all** — render a blank
plate and composite the real copy deterministically through `mockup_compositor` / `apply_label`,
where text is drawn, not guessed and then erased.
