## Where the knowledge reaches the model

`chat_adapter.build_chat_messages(query=...)` retrieves the top rules for the
turn and appends them to the system prompt as `DO` / `DON'T` pairs. A retrieval
failure returns empty and never breaks a turn — proven by
`test_prompt_unchanged_without_a_query` and `test_knowledge_reaches_the_chat_prompt`.

## Controls

- **Stop:** `state/improvement/STOP`, `python -m cie_loop --stop`, or the
  Improvement room button. Checked before every stage.
- **Dry run:** `python -m cie_loop --cycle --dry-run` (default in the API).
- **Rollback:** every promotion is a file under `knowledge/`; the cycle record
  stores `git checkout -- knowledge/`.
- **Schedule:** Windows task `NorthstarOS-Improvement`, daily 02:00, next run
  2026-10-22 02:00. Skips when the stop file exists.
- **Budgets/safety:** no money, no publishing, no ad spend, no marketplace
  calls. A cycle only writes knowledge files.

## Honest limits

1. Research is **corpus retrieval**, not live crawling. The corpus
   (`knowledge/sources/corpus.jsonl`) is curated; an online fetcher can append
   to it without changing the atom contract.
2. Coverage is measured against declared `expects` on golden items, not against
   live answer quality. The live grader exists (`cie_eval.run_suite`) but is not
   yet wired into the nightly cycle.
3. Seed atoms are `needs_verification: true` — they must be checked against the
   current Seller Central page before a customer-facing claim relies on them.
4. The 20 golden questions are a start; the plan targets 100. The harness and
   loop already support the larger set.
