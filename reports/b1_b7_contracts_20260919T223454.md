## 1. Two contract documents produced (design only)

### `docs/contracts/BFF_CONTRACT_v1.md` — B1, contract id `bff/v1`
The single response-shape law for SourceScout / ListingForge / AdPilot / SocialPulse / Golden Goose / AutoThink:
- **Uniform envelope** `{contract, request_id, status, data, error, meta}` with HTTP mapping (`ok`/`empty` 200; `error` 4xx/5xx).
- **Opaque job model** — `job_` + 32-hex ids; `queued → running → done|failed|cancelled` state machine; `scan_id`/result filenames are **internal only**; `result_ref`/`request_id` opaque.
- **Error taxonomy** — fixed codes (`invalid_request`, `forbidden`, `entitlement_required`, `not_found`, `conflict`, `provider_unavailable`, `internal_error`, …); messages leak nothing.
- **Loading/empty/error semantics** — `empty` is HTTP 200 with an enum `reason`, never a 4xx and never a faked row.
- **No-leak allowlist (§6)** — forbidden keys + forbidden value tokens (provider/vendor names, model ids, routing, cost formulas, credentials, absolute paths, stack traces), enforced later by the B4 sanitizer and audited in D1.
- **Endpoint map** — uniform job verbs per service (schemas only, no implementations).
- **Versioning** — additive within v1; breaking changes need `bff/v2`.

### `docs/contracts/GOLDEN_GOOSE_SEAM_v1.md` — B7 completion, contract id `goose-seam/v1`
Specializes `bff/v1` for Golden Goose:
- **Job model** — `service: golden_goose`, operations `goose.scan` / `goose.export`, BFF state machine; alpha scan jobs are **mock/dry-run only**.
- **Entitlement mapping** — plan id → GG categories/exports, **referencing** `shared/subscription-plans.json` (no duplicated prices/gates) plus `shared/gg-entitlements.json`.
- **Export-manifest schema** (`goose-export/v1`) with the no-vendor-leakage contract.
- **Alpha behavior table** — `POST /api/golden-goose/scan` stays **403**, unchanged; `scan-mock`/`opportunities`/`categories`/`health` documented.

## 3. Cross-check — GG `/api/golden-goose/opportunities` vs `bff/v1`

The B2 seam payload **partially conforms**; concrete required changes for Phase C (documented in `BFF_CONTRACT_v1.md` §9 and `GOLDEN_GOOSE_SEAM_v1.md` §5–6):

| Rule | Conforms | Change |
|---|---|---|
| Uniform envelope | **No** | Wrap `{contract, request_id, status, data:{items}, error, meta}`. |
| `ok/empty/error` status | **No** | `no_data` → `empty` (200). |
| Opaque job model | **No** | Add `job_id` linkage; `scan_id` stays internal. |
| No provider/vendor names | **Yes** | None. `source_store` is retailer product data (permitted). |
| No internal filesystem paths | **No — LEAK** | `report_meta.report_path` is set in `main.py` (`run_pipeline`) and echoed by the endpoint. **Must be stripped.** |
| No cost-formula/routing | **Yes** | None (net/ROI are product outputs). |

The one **material no-leak finding** is the `report_path` leak (an internal absolute path in `report_meta`); it is flagged for Phase C, not fixed here (design-only scope).
