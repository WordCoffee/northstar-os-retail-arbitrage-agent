## Procedure (staging — NOT yet executed)

1. Confirm environment is **staging** (`ENVIRONMENT=staging`) and
   `NORTHSTAR_ALLOW_STAGING_MIGRATION=1`.
2. Confirm a verified staging backup exists and restoration is possible.
3. Confirm host/database are non-production (denylist) — displayed redacted.
4. Apply rollback: `psql -v ON_ERROR_STOP=1 -U <user> -d <db> -f rollback.sql`.
5. Verify 0 foundation tables remain; verify no legacy object changed.
6. Reapply to restore: `psql -v ON_ERROR_STOP=1 -1 -f 001_foundation.sql`.
7. Re-verify fingerprints.

## What rollback preserves / removes

- **Removes:** the 25 foundation tables and any rows written after migration.
- **Preserves:** all legacy tables and any non-foundation schema.

## Failure handling

If rollback fails: do NOT manually drop remaining objects and call it successful. Capture
evidence, fix the rollback generator, recreate the disposable environment, restart from the
empty baseline.

## Authorization boundary

Rollback is authorized only for the disposable environment exercised in 1C-02R. Staging
rollback is NOT authorized and NOT executed; see `postgres-staging-readiness.json`.
